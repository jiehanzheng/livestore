LiveStore uses [Effect](https://effect.website) internally. Application code can use Effect services alongside LiveStore's public store and React APIs. Give each store one lifetime owner: a `StoreRegistry` for a React application, or `Store.Tag` for an Effect-managed application.

## Schema, equality and hashing

LiveStore uses Effect Schema for event payloads, table-column codecs and query result decoding. `Schema` is available from `@livestore/livestore` and from `effect`.

LiveStore's query and signal definitions implement Effect's `Equal` and `Hash` traits. Keep reusable query definitions outside components so consumers can share the same reactive query.

## When Effect owns the store

For an Effect-managed application, define a typed `Store.Tag` and its store layer. The operations retain the store requirement in their Effect types:

<EffectStoreSnippet />

Provide that layer at the Effect application's composition root, including the tracing service required by its layer type. Its scope owns store startup and shutdown. This is an alternative to the React registry owner shown above. Run operations through the chosen owner's runtime and handle their failures at the application boundary; creating another store layer around a registry-owned store introduces a second lifetime owner.

See [Store Effect integration](/building-with-livestore/store#effect-integration) for layer composition and multiple typed stores.
