The selected Node adapter runs persistence and synchronization in the calling Node.js process. It requires an explicit stable `clientId` and either in-memory storage or a filesystem `baseDirectory`. Set `disableDevtools: true` when creating the store.

Give each installation its own stable client ID and retain it when reopening its local data. The fixed ID in this example assumes one local installation.

The filesystem directory contains the authoritative event log as well as derived state. Keep the same directory and client identity when reopening a store. Close the store with `await store.shutdownPromise()` when its owner finishes.

## Debugging

Launch your entry point with `node --inspect-brk path/to/entry.mjs` and attach a
Node-compatible debugger. Breakpoints run in the process that owns the adapter,
including its persistence and synchronization. Use a disposable storage
directory for test writes and close the store before inspecting its database
from another process. [Node.js debugger](https://nodejs.org/api/debugger.html)

## Supported surface

This adapter exposes `makeAdapter` for Node.js. SDK worker adapters, worker logging options and LiveStore DevTools are not available. Bun and Deno compatibility have not been qualified for this selected adapter.
